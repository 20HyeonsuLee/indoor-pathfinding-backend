# 연구노트 5회차 - POI 관리 및 VPS 리버스 프록시

> **프로젝트명**: 3D 스캔 데이터 기반 실내 내비게이션 시스템
> **소속**: 한국기술교육대학교 컴퓨터공학부
> **담당**: 백엔드 서버

---

## 연구 배경

MVP에서는 목적지를 좌표로 지정해야 했으나, 실제 사용자는 "세미나실", "화장실" 같은 **이름으로 목적지를 검색**할 수 있어야 한다. 또한 클라이언트가 VPS 서비스 포트를 직접 알아야 하는 구조는 서비스 변경에 취약하므로, 백엔드를 통한 단일 진입점 구성이 필요하다.

---

## 작업 내용

### POI(관심 지점) 관리

PathNode에 POI 정보(이름, 카테고리)를 부여하여 이름 기반 목적지 검색을 구현하였다. 카테고리는 RESTAURANT, RESTROOM, CLASSROOM, ELEVATOR, STAIRCASE 등 9종이다. A* 길찾기 요청 시 목적지를 POI 이름("컴공세미나실")으로 지정하면, 해당 이름을 가진 PathNode를 검색하여 도착 노드로 사용한다.

### 턴바이턴 한국어 안내

A* 경로 결과를 사용자에게 전달할 때, 노드 좌표 목록이 아닌 자연어 안내가 필요하다. 경로의 각 구간에서 이전 이동 방향과 다음 이동 방향의 각도 차이를 계산하여 "직진", "좌회전", "우회전" 등을 판단하고, 층 전환 시에는 엣지 타입에 따라 "엘리베이터를 타고 2층으로 이동" 또는 "계단을 이용하여 이동"으로 안내한다. POI 노드 도착 시 "목적지 '세미나실' 도착"으로 마무리한다.

### VPS 리버스 프록시

VPS(:5000)로의 위치 추정 요청을 백엔드(:8080)가 중계하도록 구성하였다. 클라이언트는 백엔드 주소 하나만 알면 되고, VPS 서비스의 포트 변경이나 스케일링이 클라이언트에 영향을 주지 않는다.

## 문제점 및 해결방안

| 문제 | 원인 | 해결 |
|------|------|------|
| 좌표 기반 목적지 지정은 비실용적 | 사용자가 3D 좌표를 알 수 없음 | POI 이름 검색으로 대체 |
| 경로 결과가 좌표 배열로만 전달 | 사용자가 해석 불가 | 방향 각도 계산 → 한국어 턴바이턴 안내 생성 |
| 클라이언트가 VPS 포트 직접 접근 | 서비스 변경 시 클라이언트 수정 필요 | 백엔드 리버스 프록시로 단일 진입점 |
