# 연구노트 4회차 - 스캔 DB 이미지 추출 시스템

> **프로젝트명**: 3D 스캔 데이터 기반 실내 내비게이션 시스템
> **소속**: 한국기술교육대학교 컴퓨터공학부
> **담당**: 백엔드 서버

---

## 연구 배경

VPS 위치 추정은 카메라 이미지와 기존 맵의 특징점을 매칭하여 동작한다. 사용자가 추정 결과를 시각적으로 확인하거나, 매칭 정확도를 판단하려면 **스캔 DB에 저장된 원본 이미지를 특정 좌표 주변에서 추출**할 수 있어야 한다. RTAB-Map .db 파일은 SQLite 형식이며 각 프레임의 카메라 포즈와 JPEG 이미지가 바이너리로 저장되어 있으나, 공식 문서에 바이너리 포맷이 기재되어 있지 않아 직접 분석이 필요하였다.

---

## 작업 내용

### 포즈 블롭 파싱

RTAB-Map 소스코드를 분석한 결과, Data 테이블의 포즈 컬럼은 48바이트 블롭으로 3x4 회전+이동 행렬(Little-Endian float 12개)이다.

```
[r11 r12 r13 tx]   ← tx, ty, tz = 카메라 3D 좌표
[r21 r22 r23 ty]
[r31 r32 r33 tz]   ← r13, r23, r33 = 카메라 전방 방향 벡터
```

이 행렬에서 이동 벡터(tx, ty, tz)로 카메라 위치를, 3열(r13, r23, r33)로 카메라가 바라보는 방향을 추출한다.

### 다양한 앵글 이미지 선택

쿼리 좌표 기준 반경 내 노드를 필터링한 뒤, 카메라 방향을 3개 섹터(120°씩)로 분류하여 각 섹터에서 가장 가까운 이미지를 선택한다. 단순히 거리순으로 반환하면 같은 방향에서 촬영된 사진만 나와 위치 파악에 도움이 되지 않기 때문이다.

### 이미지 정적 파일 서빙

추출된 이미지를 `storage/images/{buildingId}/{nodeId}.jpg` 구조로 파일시스템에 저장하고, HTTP URL로 직접 접근할 수 있도록 정적 파일 서빙을 구성하였다.

## 문제점 및 해결방안

| 문제 | 원인 | 해결 |
|------|------|------|
| 포즈 블롭 구조 불명 | 공식 문서에 바이너리 포맷 미기재 | 소스코드 분석 → 48바이트 = float 12개 확인 |
| 주변 이미지 방향 편중 | 거리순 정렬만 적용 | 카메라 방향 3섹터 분류로 앵글 다양성 확보 |
| 일부 노드 좌표에 NaN 포함 | SLAM 추정 실패 프레임 | 포즈 파싱 시 유효성 검증으로 사전 필터링 |
