# 연구노트 1회차 - 연구 배경 및 시스템 설계

> **프로젝트명**: 3D 스캔 데이터 기반 실내 내비게이션 시스템
> **소속**: 한국기술교육대학교 컴퓨터공학부
> **담당**: 백엔드 서버

---

## 연구 배경

기존 실내 내비게이션은 비콘, Wi-Fi AP 등 별도 인프라를 건물마다 설치해야 하며, 설치 비용과 유지보수 부담이 크다. 본 연구에서는 **스마트폰 카메라로 건물을 스캔하면 자동으로 이동 경로 그래프가 생성되고, 이후 카메라 이미지만으로 위치를 추정하여 길찾기를 제공하는 시스템**을 개발한다. 별도 인프라 없이 카메라만으로 동작하는 것이 핵심이다.

이를 위해 해결해야 할 기술적 문제는 크게 세 가지이다:
1. RTAB-Map 스캔 데이터(.db)에서 **이동 경로 그래프(노드/엣지)를 자동 추출**하는 방법
2. 추출된 그래프 위에서 **사용자 선호도를 반영한 최적 경로 탐색** 알고리즘
3. 카메라 이미지로 **현재 위치를 추정**하고 경로 탐색과 연결하는 구조

## 작업 내용

### 시스템 구조 설계

위 세 가지 문제를 각각 독립적인 서비스로 분리하였다. 경로 추출은 NumPy/SciPy 등 수치 연산 라이브러리가 필요하여 Python 서비스로, 위치 추정은 Visual SLAM 기반이므로 별도 VPS 서비스로, 나머지 데이터 관리와 길찾기는 백엔드 서버가 담당한다.

```
클라이언트 (모바일 앱)
    │
    v
백엔드 서버 (:8080)        ←  데이터 관리, 길찾기 알고리즘, 서비스 조율
    ├──→ 경로 추출 서비스 (:8000)  ←  스캔 DB → 노드/엣지 추출 (Python)
    └──→ VPS 서비스 (:5000)        ←  카메라 이미지 → 위치 추정
              │
              v
        PostgreSQL + PostGIS     ←  3D 공간 좌표 저장
```

3D 좌표(x, y, z)와 경로 기하학(LineStringZ)을 저장해야 하므로 공간 데이터를 네이티브 지원하는 PostgreSQL + PostGIS를 선택하였다.

### 경로 그래프 데이터 모델 설계

길찾기의 핵심 데이터인 **경로 그래프**의 구조를 설계하였다.

```
Building (건물)
  └── Floor (층)
        ├── PathNode (경로 노드) ── 3D 좌표 + 유형(경유지/교차로/POI/층간이동)
        │     └── PathEdge (엣지) ── 두 노드 간 연결 + 거리 + 유형(수평/계단/엘리베이터)
        └── FloorPath (층 경로) ── 경로 추출 결과 원본 (LineStringZ)
  └── VerticalPassage (수직 이동로) ── 계단/엘리베이터, 진입점↔출구점 좌표
```

이 구조에서 PathNode와 PathEdge가 A* 알고리즘의 입력 그래프가 되며, VerticalPassage가 층간 연결을 담당한다.

## 문제점 및 해결방안

| 문제 | 해결 |
|------|------|
| RTAB-Map .db 파일이 최대 500MB로 서비스 간 전송 비효율 | Docker 공유 볼륨으로 파일시스템 직접 접근, 네트워크 전송 제거 |
| 3D 좌표에 대한 공간 쿼리 필요 | PostGIS의 Point, LineStringZ 타입으로 DB 레벨 지원 |
