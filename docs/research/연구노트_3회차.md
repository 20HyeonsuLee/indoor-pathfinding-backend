# 연구노트 3회차 - A* 길찾기 알고리즘 및 MVP 완성

> **프로젝트명**: 3D 스캔 데이터 기반 실내 내비게이션 시스템
> **소속**: 한국기술교육대학교 컴퓨터공학부
> **담당**: 백엔드 서버

---

## 연구 배경

2회차까지 스캔 데이터에서 경로 그래프(노드/엣지)를 추출하는 파이프라인을 완성하였다. 이번 회차에서는 추출된 그래프 위에서 **최적 경로를 탐색하는 A* 알고리즘**을 구현하고, **VPS 위치 추정 서비스를 연동**하여 스캔 → 경로 생성 → 위치 추정 → 길찾기까지의 MVP 전체 플로우를 완성한다.

---

## 작업 내용

### A* 길찾기 알고리즘

Dijkstra 대신 A*를 선택한 이유는, 실내 환경에서 목적지 방향이 명확하므로 유클리드 거리 휴리스틱이 탐색 범위를 크게 줄여주기 때문이다.

**알고리즘 흐름**:
1. 건물 전체의 PathNode/PathEdge를 메모리에 로드하여 인접 리스트를 구축
2. 출발 좌표에서 가장 가까운 노드를 찾아 그래프에 스냅
3. 우선순위 큐(f = g + h)로 A* 탐색 수행 (h: 3D 유클리드 거리)
4. 결과 경로를 층 전환 기준으로 구간 분리 후 턴바이턴 안내 생성

**선호도별 가중치**: 별도 로직 분기 없이 엣지 비용에 가중치를 곱하는 것만으로 사용자 선호도를 반영한다. 예를 들어 엘리베이터 우선 시 계단 엣지에 2.0배 페널티를 부여하면, A*가 자연스럽게 엘리베이터 경로를 선택한다.

| 선호도 | 수평 이동 | 엘리베이터 | 계단 |
|--------|----------|-----------|------|
| 최단 거리 | 1.0x | 1.0x | 1.0x |
| 엘리베이터 우선 | 1.0x | 0.5x | 2.0x |
| 계단 우선 | 1.0x | 2.0x | 0.8x |

### 경로 추출 결과 → 그래프 변환 (GraphBuilder)

경로 추출 서비스가 반환한 세그먼트(선분 조각)를 A* 입력 그래프(PathNode/PathEdge)로 변환하는 과정이 필요하다.

1. 세그먼트의 시작/끝점을 PathNode로 등록 (좌표 차이 0.001 이내는 동일 노드로 병합)
2. 인접 노드 간 PathEdge 생성 (거리 자동 계산)
3. 3개 이상 엣지와 연결된 노드를 교차로(JUNCTION)로 자동 분류
4. VerticalPassage의 진입/출구점을 노드로 등록하고 **수직 엣지**를 생성하여 멀티플로어 탐색 지원

### VPS 위치 추정 연동

사용자가 촬영한 카메라 이미지를 VPS 서비스에 전달하고, 추정된 3D 좌표를 A* 알고리즘의 출발점으로 사용하는 흐름을 구현하였다.

### MVP 전체 플로우 동작 확인

```
관리자: 건물등록 → 층등록 → .db업로드 → 경로추출 → 그래프생성
사용자: 카메라촬영 → 위치추정 → 목적지검색 → A*경로탐색 → 턴바이턴안내
```

## 문제점 및 해결방안

| 문제 | 원인 | 해결 |
|------|------|------|
| 부동소수점 오차로 같은 지점이 별도 노드로 생성 | 경로 추출 시 좌표 미세 차이 | 좌표 차이 0.001 이내 노드 병합 |
| A*가 같은 층만 탐색 | 층간 연결 엣지 부재 | VerticalPassage 진입→출구 수직 엣지 자동 생성 |
| VPS 장애 시 길찾기 불가 | 위치 추정 단일 의존 | 수동 좌표 입력 폴백 제공 |
