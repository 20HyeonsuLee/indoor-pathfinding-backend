# 연구노트 2회차 - 데이터 관리 및 경로 추출 연동

> **프로젝트명**: 3D 스캔 데이터 기반 실내 내비게이션 시스템
> **소속**: 한국기술교육대학교 컴퓨터공학부
> **담당**: 백엔드 서버

---

## 연구 배경

1회차에서 설계한 시스템 구조와 데이터 모델을 기반으로, 이번 회차에서는 **건물/층/스캔 데이터를 관리하는 API**와 **스캔 파일 업로드 → 경로 추출 서비스 연동**까지의 파이프라인을 구현한다. 길찾기 그래프를 생성하려면 먼저 RTAB-Map 스캔 데이터가 시스템에 등록되어야 하므로, 이 데이터 파이프라인이 선행되어야 한다.

---

## 작업 내용

### 스캔 데이터 → 경로 추출 파이프라인

사용자가 .db 파일을 업로드하면 자동으로 경로 추출이 시작되는 파이프라인을 구현하였다.

```
.db 파일 업로드 → DB에 스캔 세션 저장 (트랜잭션 커밋)
                          ↓ (이벤트 자동 발행)
               경로 추출 서비스에 처리 요청 (비동기)
                          ↓
               7단계 파이프라인 (Python)
               1. 포즈 블롭에서 3D 궤적 추출
               2. 계단/엘리베이터 수직 이동 감지
               3. PCA 기반 경로 평탄화
               4. KD-Tree + RDP 중복 제거
               5. 가우시안 스무딩
               6. 교차로 감지 및 노드/엣지 생성
               7. 시각화 (미리보기 이미지)
                          ↓
               결과를 PathNode/PathEdge로 DB 저장
```

업로드와 경로 추출을 분리한 이유는, 경로 추출에 약 30초가 소요되므로 업로드 응답을 기다리게 할 수 없기 때문이다. 도메인 이벤트를 사용하여 업로드 트랜잭션이 성공한 경우에만 추출이 시작되도록 하였다.

### 건물/층 데이터 관리

경로 그래프는 건물 → 층 → 노드/엣지 계층 구조로 관리된다. 건물 등록 → 층 등록 → 스캔 업로드 순서로 데이터가 축적되며, 건물 삭제 시 하위 데이터(층, 경로, 스캔)가 자동 정리된다.

### Docker 기반 서비스 통합

백엔드, 경로 추출 서비스, PostgreSQL을 Docker Compose로 통합하여 단일 명령으로 전체 시스템을 실행할 수 있도록 구성하였다. 스캔 파일을 두 서비스가 공유 볼륨으로 접근하여 네트워크 전송 없이 처리한다.

## 문제점 및 해결방안

| 문제 | 해결 |
|------|------|
| 경로 추출 30초 소요로 업로드 응답 지연 | 이벤트 기반 비동기 처리로 업로드 즉시 응답, 추출은 백그라운드 실행 |
| 업로드 실패 시에도 추출이 시작되는 위험 | 트랜잭션 커밋 후에만 이벤트 발행하여 데이터 일관성 보장 |
| Docker 재시작 시 업로드 파일 소실 | 호스트 디렉토리 바인드 마운트로 컨테이너와 무관하게 파일 유지 |
